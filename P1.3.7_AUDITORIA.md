## 3. Diseño transaccional de idempotencia

### Secuencia completa con pg_advisory_xact_lock

```
1. BEGIN (implícito en llamada RPC)
2. SELECT pg_advisory_xact_lock(hashtextextended(p_idempotency_key, 0))
   → Serializa TODAS las solicitudes con la misma clave
   → Se libera automáticamente al COMMIT/ROLLBACK
3. SELECT * FROM idempotency_keys WHERE key = p_idempotency_key
4. IF FOUND:
     a. Verificar user_id = auth.uid()
     b. Verificar content_hash = md5(canonical_json)
     c. Si coinciden → RETURN already_exists (sin tocar stock)
     d. Si difieren → RAISE IDEMPOTENCY_REUSE
5. Si NO FOUND:
     a. Crear temp table ordenada por product_id
     b. FOR EACH item:
        - SELECT ... FOR UPDATE (bloqueo determinista)
        - Verificar stock
        - Reducir stock
        - Calcular subtotales
     c. INSERT orders
     d. INSERT order_items (snapshots)
     e. INSERT order_status_history
     f. INSERT idempotency_keys (registra la operación)
6. COMMIT (implícito al retornar sin error)
7. Ante cualquier RAISE → ROLLBACK completo (stock restaurado)
```

### Derivación de clave de bloqueo

```sql
v_lock_key := hashtextextended(p_idempotency_key, 0);
PERFORM pg_advisory_xact_lock(v_lock_key);
```

### Manejo de colisiones de hash

- `hashtextextended` devuelve `BIGINT` (64 bits) — colisiones extremadamente improbables
- Si ocurre colisión: dos operaciones diferentes se serializan (no produce error, solo serialización)
- El contenido se verifica con `content_hash` (md5 del JSON canónico)

### Huella de contenido canónico

```sql
v_content_hash := md5(
  p_order_id || '|' ||
  p_customer_name || '|' ||
  p_customer_lastname || '|' ||
  p_customer_phone || '|' ||
  p_customer_email || '|' ||
  COALESCE(p_customer_address, '') || '|' ||
  COALESCE(p_customer_city, '') || '|' ||
  COALESCE(p_customer_postal, '') || '|' ||
  p_delivery_method || '|' ||
  p_payment_method || '|' ||
  p_items::TEXT
);
```

### Comportamiento ante timeout

| Escenario | Resultado |
|-----------|-----------|
| Cliente timeout, servidor completó | Reintento encuentra clave → `already_exists` |
| Cliente timeout, servidor falló | Rollback completo → reintento crea nuevo pedido |
| Commit exitoso + reintento | Clave registrada → `already_exists` |

### Claves vencidas y retención

**Política propuesta**: Las claves NO se borran automáticamente.
- La restricción UNIQUE en `idempotency_keys.key` previene duplicados permanentemente
- Un pedido ya creado nunca se duplica por reintento tardío
- Retención indefinida es la opción más segura (no se pierden pistas de idempotencia)

## 4. Funciones y privilegios SECURITY DEFINER

### Función `is_admin()`

| Atributo | Valor |
|----------|-------|
| Propietario | `postgres` |
| `search_path` | `''` (vacío — referencias calificadas obligatorias) |
| Ejecución | `authenticated` vía GRANT |
| Tablas lectura | `public.profiles` |
| Verificación | `auth.uid()` |
| Riesgo | Si `profiles` tiene RLS, la función no aplica RLS (SECURITY DEFINER) — correcto |

### Función `create_order_atomic()`

| Atributo | Valor |
|----------|-------|
| Propietario | `postgres` |
| `search_path` | `''` |
| Ejecución | `authenticated` vía GRANT |
| Tablas escritura | `orders`, `order_items`, `order_status_history`, `idempotency_keys`, `products` |
| Tablas lectura | `products`, `brands`, `profiles` |
| Verificación identidad | `auth.uid()` |
| RLS | No aplica (SECURITY DEFINER) — validaciones manuales en código |

### Función `prevent_role_change()`

| Atributo | Valor |
|----------|-------|
| Propietario | `postgres` |
| `search_path` | `''` |
| Tipo | Trigger BEFORE UPDATE en `profiles` |
| Verificación | `NEW.role != OLD.role` |
| Protección | Bloquea cambio de rol vía UPDATE directo |

### Corrección: SECURITY DEFINER no es service_role

**Falso**: "SECURITY DEFINER se ejecuta como service_role"
**Correcto**: La función se ejecuta con los privilegios de su **propietario** (típicamente `postgres`)

Para que actúe como service_role:
```sql
ALTER FUNCTION create_order_atomic(...) OWNER TO service_role;
```

### Promoción administrativa

```sql
-- Procedimiento explícito (no automático)
CREATE OR REPLACE FUNCTION admin_promote_user(p_target_user UUID)
RETURNS VOID
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = ''
AS $$
BEGIN
  IF NOT is_admin() THEN
    RAISE EXCEPTION 'FORBIDDEN';
  END IF;
  UPDATE public.profiles SET role = 'admin' WHERE auth_user_id = p_target_user;
END;
$$;
REVOKE ALL ON FUNCTION admin_promote_user(UUID) FROM PUBLIC;
GRANT EXECUTE ON FUNCTION admin_promote_user(UUID) TO authenticated;
```

## 6. Integridad monetaria y stock

| Validación | Implementación |
|------------|----------------|
| Cantidad entera | `~ '^[0-9]+$'` regex |
| Cantidad rango | `> 0 AND <= 10` |
| Overflow multiplicación | `IF price > 2147483647 / qty THEN RAISE` |
| Overflow suma | `IF subtotal > 2147483647 - item THEN RAISE` |
| Stock no negativo | `CHECK (stock >= 0)` + verificación en RPC |
| Orden bloqueo | `ORDER BY product_id` en temp table |
| Envío retiro | `0` (pendiente confirmar) |
| Envío domicilio | `2500` (pendiente confirmar) |
| Rollback | `RAISE EXCEPTION` → transacción aborta |

## 9. Pruebas concurrentes y negativas

| # | Prueba | Precondición | Operación | Esperado |
|---|--------|--------------|-----------|----------|
| C1 | Misma clave simultánea | Stock=10 | 2x misma clave | 1 created, 1 already_exists |
| C2 | Clave reutilización user distinto | Clave registrada | Otro user usa clave | Error IDEMPOTENCY_REUSE |
| C3 | Clave reutilización contenido distinto | Clave registrada | Mismo user, items distintos | Error IDEMPOTENCY_REUSE |
| C4 | Concurrencia stock | Stock=1 | 2 claves distintas | 1 éxito, 1 INSUFFICIENT_STOCK |
| C5 | Timeout + reintento | Servidor completó | Reintento misma clave | already_exists |
| N1 | Anónimo RPC | Sin sesión | `SELECT create_order_atomic(...)` | Error AUTH_REQUIRED |
| N2 | Insert directo pedido | Cliente | `INSERT INTO orders` | Bloqueado |
| N3 | Cambio rol | Cliente | `UPDATE profiles SET role='admin'` | Error trigger |
| N4 | Cambio total | Cliente | `UPDATE orders SET total=0` | Bloqueado |
| N5 | Stock negativo | Stock=1, qty=5 | RPC | Error INSUFFICIENT_STOCK |
